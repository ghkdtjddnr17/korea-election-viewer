# 🗳️ korea-election-viewer

> 2026 제9회 전국동시지방선거 후보 정보 뷰어 — **내 동네 투표용지**를 한눈에.

지역을 고르면 그 동네 유권자가 받는 선거(투표용지)를 **선거 순서**대로 보여주고, 후보를 나란히 비교하고, 중앙선관위 공식 사진·인적사항·공약·검증을 한 페이지에 정리합니다. 모바일 우선으로 설계했습니다.

## 주요 기능

- **지역 선택기 홈** — 광역(시·도) → 기초(자치구/시) 드릴다운
- **동네 투표용지** — 유권자가 받는 모든 선거를 NEC 투표 순서로 (시장 맨 위)
- **후보 비교** — 데스크탑은 비교 매트릭스, 모바일은 세로 카드
- **공식 후보 사진** — 중앙선관위 후보자 사진 205명 (없으면 정당색+기호 마크)
- **후보 상세** — 재산·전과·병역·5대공약·언론 검증 등 §1~14 원문
- **모바일 우선** — 전역 뒤로가기, 반응형 비교, 가독성 튜닝

## 수록 범위

| 광역 | 내용 |
|---|---|
| 서울특별시 | 시장 · 교육감 · 시의원 비례 + 관악구 · 동작구 |
| 인천광역시 | 시장 · 교육감 · 시의원(비례 · 지역구) |
| 경기도 | 도지사 · 교육감 · 도의원 비례 + 양주시 |

후보 263명 · 직책 22개 (`ELECTION_REGIONS`로 지역별 스코프 조절)

## 기술 스택

Next.js 16 (App Router · `output: 'export'` 정적 익스포트) · React 19 · TypeScript · Tailwind CSS v4 · Pretendard

## 실행

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm build        # 데이터 빌드 + out/ 정적 익스포트
```

> `data/`가 빌드 완료 상태로 커밋돼 있어, 원본 소스 없이도 `pnpm build`·배포가 됩니다.

## 데이터 파이프라인

두 시스템이 공존합니다.

- **System A (라이브)** — `scripts/build-data.ts`가 마크다운 소스 트리를 스캔 → `data/elections.json` → 캐치-올 라우터(`app/[...path]`)가 **모든 페이지**(지역·자치구·직책·선거구·후보 상세)를 렌더.
- **System B (타입드)** — 직책별 typed JSON(`data/seoul/**`) → `data/typed.json` → 리치 비교 매트릭스·상세 대시보드.

설계 메모:
- URL은 **영문 slug**(`lib/slug-map.ts`) — Next 16 Turbopack의 비-ASCII 캐치-올 이슈 회피. 화면 표기는 한글.
- 직책 정렬은 `lib/office-order.ts` (광역단체장 → 교육감 → … NEC 투표 순서). 지역 계층(광역시 vs 도)에 따라 "시의원=광역/기초"를 구분.

### 빌드 스크립트

| 명령 | 설명 |
|---|---|
| `pnpm build:data` | `elections.json` 생성 (`ELECTION_REGIONS="서울특별시,…"`로 스코프) |
| `pnpm build:typed` | `typed.json` 번들 |
| `pnpm build:nec-photos` | 중앙선관위 공식 후보 사진 수집 (이름 검색 → CDN 다운로드) |
| `pnpm build:photos` | 위키백과 사진 (레거시) |
